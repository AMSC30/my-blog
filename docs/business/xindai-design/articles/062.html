# 第八章 信贷系统的核心技术组件-（一）用户身份验证：把“你是谁”这件事做实

公众号：侃西东　·　发布日期：2026-11-18　·　微信原文open in new window

第七章把数据链路和决策引擎立起来了，这一章把信贷系统这架机器拆开，一个齿轮一个齿轮地看。

第一个判断：信贷系统说穿了是一堆专业组件的集合。很多新入行的同学以为信贷系统就是“申请、审批、放款、还款”四个页面，这是被业务功能骗了。真实的信贷系统，是由身份核验、支付、资金清结算、征信、安全等一串“专业零件”组合起来的；账务核心在第五、六章已经讲过，本章不重复。业务模块是“外壳”，这些组件才是“内脏”。业务逻辑可以各机构千差万别，但这些核心组件面对的是同一类硬问题：人怎么证明自己是谁、钱怎么从A到B、账怎么记才平、监管来了怎么查得清；问题一样，解法却各不相同。

第二个判断：这些组件有一个共同的敌人，“不可靠”。身份可能造假、支付可能失败、账可能不平、消息可能漏发、征信可能断连、数据可能被攻击。所以每一个组件，干的都是同一件事：和不可靠做斗争。你带着“这里哪里会不可靠”这个视角去读这一章，会比逐字读更有收获，因为做组件的功力，并不体现在“正常路径跑通”，而体现在“异常路径扛得住”。

这一章分九节讲核心组件，再加一组AI原生组件（升级类、新增类），我按四层来组织。第一层是交易与决策链路，身份验证、支付结算、资金清算，再加征信对接——身份验证管人是谁，支付结算和资金清算管钱怎么进出，征信管决策前看什么；第二层是支撑组件，消息通知、数据存储、安全加密，它们不直接跑交易，但所有交易都离不开它们；第三层是组装与建模：产品、额度、数据模型是一块（产品把规则组装成可售产品，额度把授信变成可控额度，数据模型给全行数据画一张蓝图）——这是建模；流程引擎和贷后管理是一块（流程引擎把零件串成可跑的流程，贷后管理把放款后的存续期管起来）——这是把模型跑起来；第四层是AI增量，既看传统组件怎么升级，也看长出了哪些新组件。你带着这四层去读，会比单个组件孤立地看更清楚它们之间的关系。

图8-1 信贷系统的核心技术组件：四层组件全景

# 一、用户身份验证：把“你是谁”这件事做实

信贷系统碰到的第一件事，不是算风险，而是认人。一笔贷款放出去之前，系统必须先回答一个最基础的问题：对面这个人，真的是他声称的那个人吗？先说用户身份验证，这是信贷系统所有决策的地基。地基不牢，后面的一切都是白搭：你给一个冒名顶替的人放了款，评分模型再准、规则引擎再严，都毫无意义，因为钱放给了错误的人。

图8-2 用户身份验证：把“你是谁”做实（节总览）

# （一）身份核验：信贷的第一道闸门

先讲清楚一个概念：信贷里的“身份核验”，和互联网产品里的“登录认证”是两回事。登录认证解决的是“这个账号的密码对不对”，身份核验解决的是“这个自然人到底是谁、他声称的身份是否真实”。前者是“钥匙对不对”，后者是“人是不是这个人”。信贷要的是后者，而且要的是强核验，因为后果是钱。

我把身份核验要回答的问题拆成三道关，你对照着看，就明白整个“核身”（身份核验的简称）体系是怎么设计的：

第一关，证真：客户上传的身份证，系统要判断是不是真实存在、有没有被PS、是不是伪造。

第二关，人真：证件是真的，不等于来的人就是证件上那个人。靠人脸比对，现场拍一张脸、跟证件照比相似度，看是不是同一个人。

第三关，活真：有人拿一张真证件照片，再配一张照片或一段提前录好的视频，想冒充本人，系统怎么防？靠活体检测，判断镜头前的是活人，而不是照片、视频、面具、3D模型。

“证真、人真、活真”三关是线上身份核验的完整骨架，三关要串起来：三关都过，才算通过；哪一关被绕过，这套核身就形同虚设。低风险、小额场景可以把核身做轻，但额度要压住，后面讲分级核身时会展开。

为什么信贷系统普遍要把身份核验做得这么重？我给你三个理由，每个背后都有教训。

理由一：冒名贷款是信贷欺诈里很常见的一类。我在做线上信贷那几年，见过太多冒名案例：黑产搞到一批身份证信息，批量注册、批量申请，钱放出去之后，真正的身份证主人毫不知情，等征信被拉黑才知道自己“被贷款”了。案件一旦发生，机构不仅要承担资金损失，还要面对客户投诉和监管问责——客户完全有理由说“我没申请过这笔贷款，是你们核身不严”。

理由二：监管把“了解你的客户”（KYC）写成了硬要求。反洗钱法、客户身份识别制度都要求在建立业务关系前完成身份识别。我在外资银行做核心系统时印象极深：一个客户开户要交的材料、要走的核验、要留的档案，比国内不少机构多得多——因为反洗钱（AML）是全球监管高压线，KYC做不好，罚单能开到你肉疼。身份识别必须做，不做就要挨罚。

理由三：身份是征信和法律的锚点。一笔贷款从签约、放款、还款到逾期追偿，所有法律行为都绑在“这个人”身上。身份核验不严，后面的一切法律动作都失去根基：合同签了等于没签，催收找不到人，诉讼立不了案。我做信贷系统二十年，最深的一条体会是：身份核验省下来的成本，最后都得用更大的代价还回去。

图8-3 身份核验：三关骨架与强核验的三个理由

# （二）核身四件套：OCR 证件识别、活体检测、人脸比对、公安实名核验

线上身份核验，落到技术上，是四件套的组合。我给你逐个讲清楚它们“做什么、怎么做、坑在哪”。

图8-4 核身四件套详解：做什么、怎么做、坑在哪

第一件，OCR证件识别，说白了就是让机器“看图认字”。客户上传身份证照片，系统把证件上的文字信息提取出来：姓名、性别、民族、出生日期、住址、身份证号、有效期。坑在于：反光、倾斜、遮挡、模糊、复印件、翻拍屏幕，都会影响识别率。所以生产级OCR不是“识别文字”那么简单，还要做“证件防伪”，判断这是不是真实的身份证，而不是打印的假证或PS过的电子版。要记住：OCR只是“读取”，不是“验证”——识别出身份证号，只说明“图上印了这个号码”，不说明“号码真实存在”，所以OCR之后必须接验证环节。

第二件，活体检测。分两种：动作活体（用户按指令眨眼、张嘴、摇头、点头，系统判断动作是否真实）和静默活体（用户什么都不用做，系统采集一段视频，用算法判断是不是真人）。技术演进就是一场军备竞赛：早期靠“动作指令”防照片，黑产用提前录好的视频就能绕过，于是先发展出“随机动作+深度模型”的动作活体，再演进到静默活体；这两年黑产又用3D面具、硅胶头套攻击，活体检测不得不升级到“近红外+深度图”的多模态方案——这正是后面要讲的AI对抗的典型战场。

第三件，人脸比对。把现场采集的人脸和证件照片（或公安库照片）比对，算出相似度分数，超过阈值判定同一人。难在“阈值怎么定”：定高了误拒率高，真客户被卡在外面，转化率受损；定低了误识率高，冒名者混进来。阈值要用真实样本测出来——我见过太多这种坑：直接上厂商默认阈值，结果误识率超标，差点放进来一批冒名申请。还有两件事得抓：一是“质量检查”，光线太暗、人脸太小、戴墨镜的照片先判不合格、让用户重拍，而不是硬比对；二是“比对源的选择”，比对证件照片、公安库照片还是历史留存人脸，效果和成本都不同，后面【技术落点】会细讲。

第四件，公安实名核验。很重的一件，也是“证真”的关键一环。把OCR出来的姓名+身份证号，通过公安部身份信息核查接口（NCIIC，全国公民身份证号码查询服务中心）核验，返回“一致/不一致/查无此人”三种结果。注意：它查的是“姓名+身份证号是否匹配”，不包含人脸比对，所以OCR、活体检测、人脸比对、公安核验这四件套齐了，才算把“证件真实+本人操作”两头都验证到。工程要点：外部接口有成本（按次收费）、有延迟、有并发限制，不能每笔都查，要设计“命中缓存+分级调用”的策略。

我把这四件套串起来，画一张线上核身的典型链路图：

图8-5 线上核身典型链路：四件套串起来

这张图的设计思路，可以拆成三件事来看。“短路”放在最前面：哪一关失败就直接终止，不浪费后面更贵的环节——公安核验按次收费，前面OCR和证件防伪先过滤一批，能省不少钱。接着是“分级”：低风险客群、小额产品走轻量核验，高风险客群、大额产品走完整四件套，这个分级策略就是【技术落点】要展开讲的成本控制。最后是“留痕”：每一关的结果、分数、照片、视频全部留档，既是监管检查和纠纷举证的依据，客户说“我没申请过”时，调出当时的活体视频和比对分数，一锤定音。

# （三）设备指纹与运营商三要素：看不见的第二道身份

四件套解决的是“这个人的身份”，但线上信贷还有一道独特难题：黑产不是一个人，是一个团伙，可能同时操控几千台设备、几万个账号去申请。光验证“每个申请人的身份”不够，还要回答：“这批申请，是不是同一伙人发起的？”这就引出第二道身份——设备指纹和运营商三要素。

图8-6 设备指纹与运营商三要素：看不见的第二道身份

设备指纹，是在用户设备上采集设备型号、系统版本、设备标识、传感器、网络环境等特征，算出一个“设备唯一标识”。设备标识这块，早年主要用网卡地址、手机串号，后来因个人信息保护收紧、系统权限受限，逐步换成安卓的OAID、苹果的IDFA这类设备标识。它有用，是因为身份可以伪造，但设备没那么容易伪造——同一批设备批量申请，把相同指纹的申请归到一起，就原形毕露。做线上信贷那几年，它是反欺诈的第一道侦察兵：一台设备短时间申请了二十来个账号，直接标红；一批设备在同一个WiFi环境批量进件，设备指纹一对，团伙特征立刻显出来。这里有三件事得抓：一是“采集要合规”，受个人信息保护法约束，不能过度采集；二是“指纹要稳定”，用户升级系统、重装APP，指纹不能大变；三是“指纹要防篡改”，黑产会用设备模拟器、改机工具伪造，所以要做“环境检测”，识别模拟器和改机环境。

运营商三要素，是把客户提供的姓名+身份证号+手机号发给运营商（移动/联通/电信/广电），核验三者是否一致，回答“这个手机号是不是这个人的”。为什么信贷要核手机号？因为手机号是线上信贷的“联系总入口”：短信验证码、还款提醒、催收联系全绑在它上面，手机号不是本人的，这笔贷款从一开始就联系不上“真正该联系的人”。局限也要说清：它只验证手机号实名信息，验证不了“是不是本人在用”，所以和活体检测、人脸比对是互补关系，不是替代关系。

讲到这儿，有个道理得说清楚：线上信贷的身份核验，是一个“多层身份”体系，证件身份（这个人是谁）、设备身份（这批申请来自哪里）、通信身份（这个手机号是不是他的）。三层身份交叉验证，才构成线上信贷的完整核身防线。黑产要骗过这套体系，必须同时伪造三个身份，成本急剧上升，这就是核身体系的设计思路：不是让攻击“不可能”，而是让攻击“不划算”。

# （四）技术落点·核身链路的组合策略与成本控制

大道理讲完，再说具体怎么做。核身绕不开的工程难题，是成本控制：公安核验按次收费、活体检测和人脸比对按调用量计费、运营商三要素也按次收费。一笔申请的成本，常见是几毛到几块钱，听着不多，但乘以每天几万笔申请就是可观开支。更要命的是，核身成本每笔都花，拦住一个冒名者的收益却只是偶尔出现，所以成本控制直接决定线上信贷产品的毛利。

图8-7 分级核身：三档组合与成本控制

我的做法是“分级核身”，把客户按风险分成三档，每档配不同的核身组合：

第一档，轻量核身（低风险客户、小额产品、已有存量客户）。新客户做OCR +运营商三要素+设备指纹初查，额度要压住；要提额或做大额支用（把额度取出来用），再补人脸比对、活体和公安核验。存量客户身份核验过、还在有效期内的，直接复用结果，不再重复OCR。目标不是“验得最严”，而是“风险可接受、客户少折腾”——每多一道环节，就多一批客户放弃，能省则省。

第二档，标准核身（普通新客户、常规产品）。OCR +运营商三要素+活体检测+人脸比对+公安实名核验+设备指纹。这是线上信贷的“主力档位”，四件套走全，运营商核验和设备指纹一个不少。成本可控，安全达标。

第三档，强化核身（高风险客群、大额产品、命中风险信号的客户）。在标准核身之上，增加公安核验频次、加人工复核，甚至要求客户补充材料（工作证明、收入流水）。大额贷款被冒名一次，损失可能远远超过核身成本，这一档，钱必须舍得花。

分级核身还有一个工程细节：档位要跟着客户走，能升能降。同一个客户，第一次申请走标准核身、贷后表现良好，第二次申请如果还是小额、低风险产品，就可以降级为轻量核身；客户命中风险信号（设备异常、行为异常），档位要能临时升级。这个“动态分级”逻辑，要配置在策略引擎里（呼应第七章的配置化），而不是写死在代码里。

再给你两个成本控制的实战技巧。第一个是“结果缓存”：在合规允许的前提下，公安核验结果在有效期内（通常24小时到7天）可以缓存，同一客户短期重复申请直接命中缓存，不用重复花钱。第二个是“异步补验”：有些核身环节不阻塞主流程，可以先让流程往下走、后补验，核身结果异步返回，不通过就在放款前拦住。提醒一句：异步补验只适合“低风险、可撤回”的场景，钱出去之前，必须确认核身全部通过。

核身和合规，最后落到一句话：核身的每一个环节，都要有“授权+留痕”。采集人脸、设备信息、调公安接口、调运营商接口，都需要客户授权（隐私政策+单独授权），每一次调用都要留痕（谁调的、调了什么、结果如何、照片视频存哪了）。第三章讲过“数据授权合规”这条红线，在核身这里它尤其严格，人脸、身份证、手机号都属于敏感个人信息。核身系统上线前，建议先做一次个人信息保护影响评估（PIA），把数据流转路径理清楚再动手。

# （五）AI 增强：Deepfake 对抗、声纹识别、多模态核身

传统核身说完，再看AI时代的攻防。核身领域，是AI应用里攻防面对面较量的地方，因为攻防双方都在用AI：黑产用AI造假，机构用AI识假。有三个变化正在发生。

图8-8 AI 增强：Deepfake 对抗、声纹识别、多模态核身

第一个变化：Deepfake对抗。这是当下核身面临的主要威胁之一。Deepfake（深度伪造）技术可以用AI生成以假乱真的人脸视频，一张照片就能驱动出一个“活生生”的人脸，可以眨眼、张嘴、摇头，甚至可以实时换脸。前几年，这类攻击还只能对付“动作活体”，但随着深度伪造技术进化，现在连静默活体的防线都面临冲击。应对之道是“对抗式升级”：活体检测模型要用深度伪造样本持续训练；同时引入“近红外活体”，近红外摄像头采集的人脸，和可见光下的画面有明显差异，伪造视频很难模拟近红外特征，这是目前对抗Deepfake比较有效的一道防线。我的看法是：Deepfake对抗没有一劳永逸的方案，只有“持续对抗、动态升级”，核身模型要像风控模型一样，上线后持续监控、持续用新攻击样本重训。

第二个变化：声纹识别。声音也是一种生物特征。声纹识别在信贷里的典型场景是电话核身，客户打电话到客服中心办理业务（修改联系方式、查询敏感信息），用声纹确认“你就是你”。声纹识别的价值在于“非接触、无感”，客户正常说话，系统后台就完成了身份确认，体验比人脸比对更顺滑。但声纹识别的短板也很明显：受环境噪声影响大、采集设备不同会影响识别率、录音重放攻击（黑产录下客户的语音再播放）需要专门防御（随机语句挑战可以防录音重放）。所以声纹识别在信贷里目前是“辅助核身”，配合其他因素一起用，而不是单独作为核身依据。

第三个变化：多模态核身。这是核身技术正在走向的方向，不再依赖单一生物特征，而是把人脸、声纹、行为、设备、证件等多个信号融合起来综合判断。它的逻辑是：单一模态都可能被伪造，但“同时伪造所有模态”的成本急剧上升。比如一个客户，人脸比对分数中等偏上、声纹匹配、行为模式正常、设备历史干净，单看任何一个信号都不足以定论，但四个信号指向同一个结论，可信度就很高。多模态核身是典型的“AI原生组件”（这一章第十节会展开），它的实现要解决“多信号怎么融合”和“融合结果怎么解释”两个问题，前者是技术问题（加权、模型融合），后者是合规问题（拒绝客户时，要能说清是哪个信号触发的拒绝）。

AI时代的核身，有一条原则得先说在前面：别相信“某个技术是万能的”。人脸识别会被Deepfake骗、声纹会被重放攻击、活体会被3D面具骗，核身的正确姿势，还是“多层防线+持续对抗+人工兜底”。技术负责把攻击成本抬到足够高，人负责处理“技术判断不了”的边界情况。这是核身领域用AI的第一条规矩。

# 【监管红线提示·生物特征信息的保护】

做身份核验，有一条红线比“核验通过率”更重要：生物特征信息的保护。人脸、声纹、指纹，都属于敏感个人信息，受个人信息保护法的严格保护。采集要单独授权（不能藏在用户协议里）、存储要加密（人脸模板、声纹模型必须加密存储；原始照片、视频、录音要按监管留档要求加密保存，到期删除，不能明文散落）、使用要限定场景（只能用于核身，不能挪作他用）、删除要有机制（客户注销、业务结束，生物特征信息要按规定删除）。有个细节特别容易被忽略：人脸照片和视频，是“能直接识别到个人”的生物特征数据，一旦泄露，后果往往更麻烦，因为脸改不了。做核身系统的人，请把“生物特征数据的全生命周期保护”当成和“核验准确率”同等重要的事来抓。

# （六）图计算与关联网络：把团伙和担保圈画出来

前面讲设备指纹，回答的是“这批申请是不是同一批设备发起的”。但团伙是一张网：几千台设备、几万个账号、上万个手机号，背后可能是同一拨人。要识破它，光验单个客户不够，得把“人和人、设备和设备、企业和企业”之间的关系画出来。这一小节讲图计算，信贷里专门干这个的组件。

图8-10 图计算与关联网络：点、线、网与三个核心场景

把客户、设备、手机号、IP、账号、企业、实际控制人当成“点”，把“用过同一台设备、同一个手机号、互相担保、资金往来”当成“线”，点和线连起来就是一张网。图计算，就是在这张网上做分析的功夫：查某个点两跳以内都连着谁，把抱团的点圈出来，把成环的关系找出来。

信贷里图计算很能派上用场的地方，首先是团伙欺诈：黑产群共用设备、共用手机号、共用收款账户，社区发现算法能把这群人整窝端出来。多头借贷也是图计算的强项，同一个手机号或设备关联十几笔申请，图上一眼看出谁在“以贷养贷”。对公那边很典型的是担保圈，企业互相担保、联保、循环保形成的环，环里一家违约会传染一串，图算法专门找环和紧密社区，这是传统报表很难看出来的。

具体怎么做，是把申请记录、设备指纹、交易对手、担保关系这些数据入图，用图数据库或图引擎存和查（Neo4j这类），线上查“K跳邻居”（和这个手机号两跳以内都有谁），离线跑团伙发现。公开报道里，工行用知识图谱团伙挖掘算法识别隐性关联，长安银行用“知识图谱+大数据”识别担保圈和多头借贷，也有农商行用图数据库拦截涉诈资金。图计算不替代规则引擎，它给规则和模型喂“关系特征”，一个“和逾期客户两跳以内”的特征，比一堆单点特征都好用。
