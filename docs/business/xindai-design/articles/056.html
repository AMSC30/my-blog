# 第七章 数据驱动的信贷决策-（二）信用评分模型：把“风险”算成“分数”

公众号：侃西东　·　发布日期：2026-11-12　·　微信原文open in new window

二、信用评分模型：把**“风险”算成“分数”**

数据采进来了、洗干净了，接下来要做的事，是把“风险”量化。这一节讲信用评分模型，信贷决策里最核心、也最有历史的一环。在讲模型之前，我想先带你看看信用评估这门手艺是怎么进化的，因为现代评分卡的每一步，都能在老的信用分析方法里找到影子。

# （一）从6C 到 FICO：信用评估的进化史

信贷行业管“评估一个人靠不靠谱”这件事，管了几百年。老一代信贷人总结出6C、5W、5P这些经验框架，还流传一个“10-80-10法则”：客群里约10%是优质客户、10%是高风险客户，中间80%是普通客户，风控的重点和资源分配要围绕这个分布设计。我自己在《信贷基础知识》里也整理并讲过这套法则。这些方法看着老派，但里面的智慧一点不过时。

把信用评估变成“一门科学”的，是FICO评分：1950年代，工程师Bill Fair和数学家Earl Isaac创立FICO公司，把“凭什么判断一个人信用好坏”从主观经验变成了可计算的数学模型。

FICO留下的最关键的东西，是“用分数说话”这个思路，算法反而在其次。没有评分之前，两个客户经理对同一个客户可能给出完全相反的判断；有了评分，一笔贷款能不能批、批多少，就有了一个客观的起点。从“人说了算”到“分数说了算”，这条演化线，见图7-3。

图7-3 信用评估的进化史：从 6C 到 FICO

讲到这里，我先插一句我自己的真事，免得你把“评分卡”想岔了。我刚做信贷系统那会儿，第一次在需求文档里看到“评分卡”三个字，下意识以为它和银行卡、信用卡有点关系，毕竟都带个“卡”字。后来看明白才恍然大悟：评分卡就是评分系统，“卡”和卡片半毛钱关系都没有，它指的是“把评估结果排成一张卡（表）”的模型。这个乌龙，后来我跟不少新入行的同事都讲过，信贷行业里很多名词都是这样，字面意思会骗人，别望文生义，得看它的实际功能。

顺着功能说，评分卡其实是一大家子。按环节分：申请评分卡（贷前，看基本信息，评估能不能放）、行为评分卡（贷中，看贷后行为，动态评估）、催收评分卡（贷后，评估逾期客户催收的优先级和方式），再加反欺诈评分卡（评估骗贷风险）。我更看重行为评分卡，它和申请评分卡最大的不同，是用“行为数据”而不是“申请数据”：你贷后怎么还钱、用卡用得多不多、额度占用率多高，这些行为比当初申请时填的那一栏栏信息更能反映真实风险。国有大行有个做法很典型：在申请环节就调用“信用卡行为评分卡”，看客户在信用卡上的行为评分和额度使用率两项，判断他是不是“潜在通过客户”。这其实是拿“贷后行为”反哺“贷前决策”，也是数据驱动的例子。

# （二）逻辑回归评分卡：可解释的老伙计

讲完了历史，回到技术。信贷行业最经典的评分模型，是逻辑回归评分卡。为什么它到今天还是主力？两个字：可解释。黑箱模型再好，解释不了，在信贷这种强监管行业就上不了大梁。

逻辑回归评分卡的构建流程，我简化成四步，每一步都对应明确的工程动作：

第一步，样本与好坏定义。这是评分卡的地基，也是最容易出问题的一步：先定义“好客户”和“坏客户”，通常把逾期超90天或进入不良的定义为“坏”，正常还款定义为“好”。这一步还有个信贷行业特有的难题叫“拒绝推断”——被拒绝的客户没有贷后表现、好坏未知，怎么处理这批“沉默样本”，是评分卡技术的经典课题。

关于“坏样本”怎么定，行业惯例是M3及以上的逾期（连续逾期三个月及以上），加上债务重组、个人破产、银行主动关户等情形。这个定义直接决定模型学什么——定义松了，模型把真正的坏客户当好客户；定义严了，坏样本太少，模型学不到东西。M0到M3的逾期分级、口径怎么定才经得起审计，第九章“样本定义”一节会完整展开。

好坏的定义定下来，还要先立一个时间框架：观察期和表现期。观察期是收集特征的时间窗口，表现期是观察客户是否触发坏样本的时间窗口，中间的分界叫观察点。记住一条就够：观察期收集“因”，表现期观察“果”，模型学的就是“观察期的因”到“表现期的果”的关系。窗口取多长，得两头权衡：表现期太短，坏客户还没暴露；太长，样本又太旧。

第二步，特征工程与分箱。评分卡有个特点：连续变量要“分箱”，把年龄分成18-25、26-35、36-45、46以上几档，而不是把原值直接扔进模型。为什么分箱？一来捕捉非线性（年龄和风险是U型关系），二来模型更稳健，三来能把“缺失值”单独成箱——数据缺失在信贷里太常见了，把“缺失”当成一个诚实的箱带进模型，比硬生生补一个值好得多。分箱的主流方法，第九章“评分卡体系”一节会讲透。

上面讲的，主要是零售信贷的逻辑——看个人征信、消费行为、APP使用习惯。做对公风控时，特征体系完全换一套：不看个人刷了多少抖音、点了多少外卖，看的是企业财报、增值税开票、银行对公流水、纳税信用评级。这些数据更稳定，但更新频率更低，模型迭代比零售慢很多，对可解释性的要求也更高。

第三步，WOE与IV。分箱之后，每个箱要算两个值：WOE（证据权重）和IV（信息价值）。WOE衡量的是“这一箱里的坏客户比例相对于整体偏高还是偏低”，IV衡量的是“这个变量整体上区分好坏客户的能力”。特征选择就是用IV说话：IV高的留下来，低的剔除。这里我只强调一点：这一步看着是技术活，其实是业务活——你选的每一个变量，都要能回答“它凭什么预示风险”，说不清的变量，再高IV也慎用，因为它可能是过拟合或者数据陷阱。

WOE这东西听起来玄，我用大白话讲透它的价值：把每个变量的每档都算出一个WOE，再乘上模型系数累加，就是客户的最终评分——评分卡打分，说白了就是“把客户的各个特征翻译成一个个WOE，再加权求和”。这个翻译过程是可解释的：客户为什么是这个分，拆开来看，每一档特征各贡献了多少，一清二楚。我见过真实银行评分模型的公式，比如某个个人消费贷款评分卡：分值=基准项- 0.9073×账户利息WOE - 0.297×一级分行WOE - 0.9687×贷款用途WOE - 0.5531×最高学历WOE - ……哪个变量贡献大、哪个小，一目了然。这种“一个公式说得清”的透明，是黑箱模型给不了的。

光说定义你可能没感觉，我拿一组真实的数值给你看。这是我当初做住房贷款评分卡时见过的学历变量WOE对照表：

表7-1 学历变量 WOE 值示例

学历分箱WOE值
研究生及以上0.24847
大学本科0.12254
大专和专科学校0.02331
中专/技校/高中-0.12280
初中/小学/文盲-0.22217

你看这组数：WOE为正的（研究生、本科、大专），代表这一学历档次的客户整体比平均水平“更安全”；WOE为负的（高中及以下），代表“更危险”。学历越高越安全，和业务直觉一致——评分卡为什么可解释？道理就在这儿。

第四步，标准分转换。最后把逻辑回归的输出，通过一个线性变换，映射到标准分区间（比如300-850或200-1000）。标准分的好处是直观：分数和违约概率挂上钩，分数越高，违约概率越低，分数每提高多少分，违约概率下降多少，可以精确计算——“一个分数代表一个风险等级”就是这么来的。转换公式（偏移量offset、比例因子factor怎么定）是评分卡的硬核，第九章“标准分转换”一节会完整推导。

我讲这些，不指望你立刻去建模型（那是第九章的事），只想让你对“评分卡是怎么工作的”有个大概的印象。你只需要记住一条：评分卡的灵魂是“分箱+权重+标准分”，它把一堆原始变量，翻译成一个可解释、可计算的分数。逻辑回归评分卡的这条四步流水线，见图7-4。

# （三）机器学习模型：GBDT、XGBoost 与神经网络

评分卡讲完，说说新一代模型。数据量上来了、算力也够了，机器学习模型在信贷风控里用得越来越普遍，最主流的是两大类：GBDT和神经网络；再加上前面讲的评分卡，模型家族一共三类。实际生产里还有一种组合打法，把这三类搭起来用。

第一类，GBDT系列（梯度提升树），包括XGBoost、LightGBM，是当前信贷风控里用得最多的一类：自动处理非线性、变量交互和缺失值，训练快效果好，但代价是可解释性明显下降——XGBoost能告诉你“哪些特征重要”，很难告诉你“为什么这个客户得了这个分数”。如果说评分卡是“手工作坊”，GBDT就是“工业化流水线”，把原始特征扔进去，它自己就能学到复杂的模式。这些模型的原理和边界，第九章“常见的风控模型”一节会展开，这里记住“怎么选”就行。

第二类，神经网络/深度学习。它在信贷里的应用有明确边界：擅长非结构化数据——图像、文本、序列，比如CNN（卷积网络，擅长看图）识别伪造证件、LSTM/Transformer（擅长看序列）分析时序行为、图神经网络（擅长看关系）分析关联关系；但对最核心的“结构化特征打分”，GBDT往往不输甚至更好，且成本更低。所以，深度学习要用在刀刃上——用在非结构化数据上，别在结构化表格上硬刚GBDT。

说完两类模型，还得补一句“模型集成”。信贷生产环境里，几乎不存在“一个模型打天下”的情况，主流做法是“模型栈”：评分卡做基础打分（可解释、可审计），GBDT做精细预测（效果好），深度学习处理非结构化信号，最后用策略引擎组合成最终决策。实际生产里，电商、小微企业、个人、学生这些客群，也是这么分开建模、最后汇总决策的——不同客群、不同数据，用不同模型。

模型选型和组合打法讲完，还得补一个信贷建模绕不开的坑：非平衡样本。信贷数据的天然结构是正常还款客户是绝大多数、违约客户是极少数，这种“好坏严重不均”的数据直接扔给模型，模型会“偷懒”：全预测成好，准确率也有99%，但对坏客户几乎没有识别能力——这恰恰是风控最不能丢的能力。解决它有三招：过采样（复制少数类，简单但容易过拟合）、欠采样（抽多数类，简单但会丢信息）、SMOTE（把少数类样本合成一些新的，最常用）。非平衡的“度”很难拿捏：过采样过头，模型会学偏；欠采样过头，坏样本又不够。所以老手常说：非平衡处理不是“一键解决”的开关，是在“识别坏客户”和“不误伤好客户”之间反复权衡的平衡术。

问题也跟着来了：有GBDT这么好用的模型，为什么还要评分卡？这就回到了信贷行业的特殊约束。我把它总结成“模型三问”：

第一问，可解释吗？监管要求你回答“为什么拒”，评分卡能答，GBDT很难答。这不是“监管不懂技术”，是“金融必须讲得清”。所以你经常看到的实际架构是：GBDT做“风险排序”和“额度建议”，评分卡做“决策依据”和“合规解释”，两者配合。

第二问，稳定吗？模型上线后，特征分布会漂移、客群会变化，模型会慢慢“过时”。评分卡结构简单、依赖的变量少且稳，漂移相对可控；复杂模型对特征漂移更敏感，需要更频繁的监控和重训。这引出第十一章要讲的模型监控——PSI（评分分布的稳定性指标）、特征漂移、定期重训，都是为这件事服务的。

第三问，对抗性呢？信贷风控有一个其他领域没有的敌人：黑产。规则和模型一旦被黑产摸清，就会被针对性地绕过——评分卡规则简单，容易被逆向；复杂模型更“抗逆向”，但也可能被对抗样本攻击。所以真实的风控体系不是“一个模型”，是“规则+多模型+动态调整”的组合，让黑产摸不透你的底牌。这两类模型怎么选、怎么组合、非平衡样本怎么处理、为什么还要评分卡，图7-5把这几件事摆在一起看。

# （四）从评分到额度：score-to-credit-limit

评分不是终点，终点是“给多少额度、定多少利率”。这一小节，讲从评分到额度的映射，这是决策输出的关键一步。

原理很简单：分数代表风险，风险决定你“敢借给他多少钱、以什么价格借”。映射通常是一张“分数-额度”对照表：评分在某个区间，对应某个基础额度档位，再叠加收入、负债率、担保、产品限额这些修正因子。在民营银行管额度系统那会儿，就是这个思路。风控系统跑出评分和额度建议，额度系统按“先机构、后客户”的框架来做：先把客户分成自然人、非自然人两类，再在总机构下控制客户授信总额，额度最终落到“机构—客户—产品”这一层。同一个客户在不同产品下各有额度，产品规则决定额度怎么开、怎么用、怎么改状态、怎么释放。

这里我要点出一个信贷系统特有的概念：额度和放款是两回事——授信额度是“我给你一个可以循环使用的上限”，支用是“你在这个上限内实际借出钱”，额度系统管的就是开通、支用、变更、冻结解冻、到期这一串动作。我在额度系统里见过最典型的链路是“风控驱动额度”：风控跑出目标客户和额度标签，以文件或接口形式推给额度系统，额度系统按标签重算额度、触发额度变化。一条完整的“评分→额度”数据链路，就这么跑通了：风控算的是“这个客户值多少钱”，额度系统管的是“这笔钱怎么给出去、怎么收回来”。

# （五）技术落点·评分卡到额度的映射表

把从评分到额度的过程，画成一张可直接复用的映射示意：

表7-2 评分到额度与利率的映射示意

评分区间风险等级基础额度档位利率档位说明
780及以上极低风险30万基准-20%自动通过
700–779低风险20万基准-10%自动通过
650–699中低风险10万基准自动通过+抽查
600–649中风险5万基准+10%人工复核
550–599中高风险2万基准+30%人工审批为主
549以下高风险拒绝—自动拒绝

这张表有三点你要注意。第一，映射并非一锤定音，它由“基础档+修正因子”组成：收入、负债率、担保、多头等会调整最终额度。第二，额度档位要能“动态重估”：贷中表现变好，额度上浮；出现风险信号，额度下调或冻结——这就是行为评分卡（B卡）的用武之地。第三，映射规则要可配置、可灰度、可回看：评分区间调整了、额度档位变了，要能追溯“为什么这个客户拿到了这个额度”。

说到“评分区间”，我再补一个几乎每套评分卡都会有的概念：Cutoff（阈值）。评分不直接用来发额度，它先把人“分群”——高分段直接过、低分段直接拒、中间段人工看。Cutoff是“参数化”的，配置在策略表里，风控部门随时可调：调高，通过率下降、风险更稳，但可能误伤好客户；调低，业务冲量，但风险敞口变大。它和排除政策、硬政策、挑选政策合起来就是完整的“评分卡政策体系”，那是决策引擎一节的主角，具体分档和机制细节到那里再展开。评分到额度的这条链路，见图7-6。
