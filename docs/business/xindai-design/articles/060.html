# 第七章 数据驱动的信贷决策-（六）AI 时代决策：大模型与知识增强

公众号：侃西东　·　发布日期：2026-11-16　·　微信原文open in new window

六、AI 时代决策：大模型与知识增强

讲完了传统决策的全链路，咱们换个角度，看看正在发生的变化。这一章从“数据怎么采”讲到“决策怎么出”，底盘一直是“规则+模型”。但AI时代，这套底盘上又多了一层能力：知识库接进来，大模型加进来，决策开始往智能化方向走。这一节，我讲大模型如何参与决策，以及它的边界在哪里，这也是全书“AI时代”主线在这一章的具体落点。

# （一）大模型辅助决策：从“人写规则”到“人说人话，系统出规则”

先说大模型参与决策的第一个层次：策略配置的自然语言化。

传统信贷策略的配置，是“技术语言”的：业务人员说“多头超过6次就拒”，系统实现却是一堆参数、代码、配置表。中间有一道“翻译”的鸿沟——业务不懂技术，技术不懂业务，一条策略从想法到上线，要经过需求、开发、测试、发布，以周计。这道鸿沟，正是大模型可以填的第一个坑。

用大模型做“自然语言配置策略”：业务人员用自然语言描述策略——“近三个月在6家以上机构申请过贷款的客户，直接拒绝；但在本行有良好还款记录的存量客户除外”。大模型把这个描述解析成结构化规则（条件字段、操作符、阈值、例外），再自动生成规则引擎能执行的配置。工程价值很直接：策略变更从“改代码”变成“说一段话”，上线周期从“周”压缩到“小时”。

但这里得泼一盆冷水，也是我做AI应用很深的一条教训：自然语言配置策略，大模型只能做“草稿”，不能做“定稿”。策略是“带责任”的，一条错了，可能直接带来坏账，也可能误拒客户。大模型解析自然语言，可能漏掉一个“除外条件”，也可能把“6家以上”理解成“6家及以下”——这些错误在草稿阶段可以发现，但绝不能直接上线。正确的做法是“人机协同”：大模型生成规则草稿→风控人员审核确认→确认后才生效。大模型负责“提效”，人负责“把关”。这个模式，就是全书说的“人在环里”（Human-in-the-loop），在策略配置上的具体做法。自然语言配置策略的链路与人机协同流程，见图7-22。

# （二）决策原因解释：让模型“讲人话”

大模型参与决策的第二个层次，是决策原因的自然语言解释。

前面讲过，决策要可解释、可回溯。但传统可解释是“技术可解释”：能查出来“命中哪条规则、评分多少分”，对监管和工程师够用，对客户不够友好。客户收到“您的申请未通过”，只是一个冷冰冰的结果，背后的原因看不懂。而消费者权益保护的方向，是让客户知道自己为什么被拒。矛盾就在这里：系统能给的是“技术原因”，客户要听的是“人话原因”。

大模型恰好能填这个坑：把结构化的决策原因（命中规则、评分区间、风险标签），翻译成客户能听懂的自然语言——“您的申请因近期借贷申请较为频繁而未通过，建议您间隔一段时间后重新申请。”这句话，大模型可以根据决策快照自动生成。它不编造原因，只把决策档案翻译成人话：不改变决策，只改善“解释”。

这里强调一个边界：大模型做“解释”，得基于“决策快照”这个事实，不能自由发挥。客户被拒的真实原因是“多头超限”，大模型就得说“多头超限”，不能说成“综合评分不足”这种含糊话术。这要求“解释生成”和“决策快照”强绑定，大模型只能从快照里取事实做翻译，不能凭空生成。我在AI合规上一直讲一条：大模型可以“组织语言”，但不能“创造事实”。决策解释尤其如此——解释的事实依据，只能是决策时点真实发生的数据和规则。从决策快照到客户话术的翻译链路与边界，见图7-23。

# （三）决策知识库：把风控经验与监管规则沉淀为“知识”

大模型参与决策的第三个层次，是知识库的构建。这一块，是“特征+模型+知识”三路里“知识”这一路的落点。

先说一个业务上的痛点。信贷机构里，很值钱的资产除了数据，还有“知识”：风控专家脑子里那套“什么情况要警惕”的经验、监管文件里的“红线”、历史案例沉淀的教训。这些知识过去存在哪？存在老师傅的脑子里、一摞没整理的文档里、会议室的口口相传里。新来的风控人员要熬很久才能“入门”，因为知识没被沉淀、没被检索、没被复用。这就是“知识流失”：人走了，经验就带走了。

大模型时代的解法是“决策知识库”：把风控经验、监管规则、历史案例、产品政策，整理成可检索的知识资产，通过RAG（检索增强生成）技术，让大模型“带着知识回答问题”。它解决的正是“知识沉淀”和“知识检索”两件事。具体来说：

第一步，知识整理：把散落的材料整理成结构化知识——监管办法（利率上限、催收规范）、风控策略说明（每条策略为什么这么定、有什么坑）、历史案例（某类欺诈团伙的特征、某次误拒的复盘）、产品政策（各产品的准入、定价规则）。第四章讲过RAG知识库的搭建，这里强调它的决策价值：知识库让“风控经验的复制”成为可能，老师傅的经验被整理进知识库，新人的成长曲线会短一大截。

第二步，知识检索增强：风控人员问“这个客户的异常要怎么处理”，或决策系统需要判断“这笔业务有没有踩监管红线”时，先从知识库里检索出相关片段（相关监管条款、相关历史案例、相关策略说明），喂给大模型，让它在“权威知识”的基础上作答。这样答出来的结果有依据、可溯源——大模型引用了哪条监管文件、哪条历史案例，都能追溯。

第三步，知识的持续更新与治理。知识不是死的，监管在变、策略在变、案例在累积。知识库要有明确的更新机制和责任人：谁维护、多久更新、如何审计。第四章讲过，AI时代的“知识资产”要像管钱一样管起来。决策知识库尤其如此——一条过时的监管条款，如果还躺在知识库里被大模型引用，比“不回答”更危险。从知识整理到检索增强再到持续治理，三步连起来，见图7-24。

# （四）“特征 + 模型 + 知识”三路融合的智能决策架构

把前面讲的AI能力和传统决策链拼在一起，我画出这一节的总图，AI时代的智能决策架构。它的核心就一条：决策从“单一路径”变成“三路融合”。

第一路，特征路，回答“这个客户是什么样”：客户特征、行为特征、征信数据、实时信号，通过特征平台统一供给。第二路，模型路，回答“这个客户风险有多高”：评分卡、GBDT、神经网络，输出风险分数和概率。第三路，知识路，回答“这笔业务合不合规、以前怎么处理、专家会怎么看”：监管规则、风控经验、历史案例、产品政策，通过知识库和大模型供给。

三路融合的决策是这样一个过程：三路信号在决策引擎里汇聚，加上规则，形成最终决策——特征路供实时数据、模型路打风险分、知识路用大模型结合知识库做“语义层面的补充判断”，比如从申请文本、授权获取的交互记录里识别风险信号，或对照监管条款检查合规性。

用一个具体例子看懂“三路融合”和传统决策的区别。一笔小微经营贷申请：传统决策看的是“特征+模型”——评分够不够、规则过不过。三路融合额外加了一路“知识”：大模型读取申请材料里描述的经营场景，结合知识库里“同类行业的风险特征”，识别出“这个经营场景和常见的骗贷话术高度相似”，给决策引擎一个“风险提示”。这个提示不替模型做决定，只给决策增加一个知识层面的信号——三路结合，比单靠一路判断更全面。

这里强调三路融合的一个设计原则：知识路是“增强”而不是“替代”。模型路给出的评分是“量化判断”，知识路给出的提示是“语义判断”，两者互补，各管一层。最终决策仍然由决策引擎（规则+模型）做主，知识路提供“增量信号”。为什么要这样？因为模型路可量化、可回溯、可监控，知识路（大模型）目前还做不到，所以知识路只能“辅助”，不能“主导”。这个边界，下一小节专门讲。三路融合的智能决策架构，见图7-25。

# （五）大模型决策的边界：什么时候可以相信，什么时候必须Human-in-the-loop

讲完大模型能做什么，我得花一整小节讲它不能做什么。这是我做AI金融应用最想传递给读者的东西：AI不是万能的，尤其在信贷这种“真金白银+强监管”的行业，知道“边界在哪”，比知道“能做什么”更重要。

我把信贷决策里的任务，按“能不能交给大模型”分成四类，你直接拿去对照：

表7-5 大模型决策的边界：什么时候可以相信，什么时候必须 Human-in-the-loop

决策类别代表任务风险·属性大模型角色人的角色关键要求
第一类：完全可交给大模型知识问答、材料整理、报告草拟、话术生成、决策原因解释低风险·辅助性自主执行（有事实依据约束）事实验证错了影响可控，放心用
第二类：大模型辅助、人工把关策略配置草稿、尽调报告辅助、审批辅助中风险·专业性提效减负决策把关信贷AI落地的主战场，风险可控、见效快
第三类：大模型提供信号、决策引擎决策语义风险识别、知识增强判断中高风险·决策性输出“信号”，不是“决策”规则+模型做最终决策信号可解释、可监控、可回退
第四类：绝不能交给大模型放款决策、额度批复、利率定价、扣款指令高风险·资金性绝不自主决定人机协同、人工兜底幻觉、责任、可解释三道坎，“动钱”的事人工做主

这四类边界，我再用一个更朴素的判断标准总结给你：看这个决策“错了的后果”和“解释的难度”。后果轻微、可解释的，放心交给大模型；后果中等、需要专业判断的，大模型出草稿、人把关；后果落在业务决策上、还能用规则和模型兜住的，大模型只出信号、决策引擎拍板；涉及真金白银、责任重大的，人工做主。这个标准，换到别的AI应用场景也基本适用；不管技术怎么发展，信贷行业“真金白银+强监管”这个底色不变，大模型的能力边界就在那里。

这里我还想补一个更长远一点的观察。很多人问我：大模型能力越来越强，会不会有一天真的能全自动做信贷决策？我的回答是：技术上也许有一天能接近，但“责任”这道坎一直在。信贷决策不是“算得对不对”的问题，是“谁负责”的问题。只要监管还要求“决策可解释、责任可追溯”，信贷决策就必须保留“人的位置”，哪怕这个“人”只是在监督一台极其聪明的机器。所以信贷AI该走的路，是“让AI帮人变得更强”，不是“让AI取代人”。

比大模型决策更进一步的是决策智能体，它不只是回答问题，而是能自主完成“收集信息→分析→生成方案→执行”的完整决策链。信贷领域的审批智能体、额度定价智能体正在探索中，但受限于可解释性和责任归属，目前都处于“辅助决策”阶段，完全自主决策还需要时间。第十五章第五节会专门讲智能体在信贷怎么用。

# 【作者手记】一次风控数据延迟引发的坏账

很多年前，我在一家互联网信贷平台做风控系统。当时多头借贷数据从第三方数据源拉取，每天定时批量更新，最多有24小时延迟。

问题就出在这个延迟上。一批撸口子的职业骗贷客（专门钻平台空子骗贷的人），同一天向十几家现金贷平台发起申请，专挑多头数据更新慢的平台下手。他们第一天集中申请，系统用昨天的数据把他们当干净客户放行，第二天数据更新才看到多头数严重超限，但钱已经放出去了。那批坏账直接拉高了我们那个季度的不良率。

复盘后上实时多头监控，把时延从24小时压到分钟级。这件事给我三个教训：第一，决策质量取决于数据新鲜度，再好的模型喂给过期数据也是空转；第二，关键数据源要盯时效，上次更新时间、延迟多少、有没有断供；第三，外部数据延迟时要有降级预案，宁可保守收紧，也不要冒险用过期数据放行。
